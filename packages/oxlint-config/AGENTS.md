# @aliexme/oxlint-config

Shared oxlint configuration — raw JS typed with `defineConfig` from `oxlint`, no build step, published as-is: `index.js` (the base config) and `configs/vitest.js` (an opt-in Vitest preset exposed as the `./vitest` export).

- `oxlint` (`^1.87.0`) and `oxlint-tsgolint` (`^7.0.2004`) are optional peer dependencies (the latter is required only for type-aware linting); the package has no `scripts`.
- The `plugins` field overwrites the default plugin set, so it is pinned explicitly to the oxlint defaults (`eslint`, `typescript`, `unicorn`, `oxc`) plus the `import` plugin; `react` is deliberately not included — consumers opt in by setting `plugins` in their own config (the field replaces the whole set). The `correctness`, `suspicious`, `pedantic`, `style` and `perf` categories are enabled, raised to `error` so findings fail CI without extra flags. The `restriction` category is disabled — its rules are adopted explicitly in `rules` with lockstep options where applicable; noisy rules that fire are off-listed in `rules`.
- `configs/vitest.js` is the opt-in Vitest preset (`@aliexme/oxlint-config/vitest`): consumers add it to `extends` after the base config; not extending it is the opt-out. `extends` merges the `plugins` lists, so the preset declares only `vitest` — the base categories pick up the vitest rules; noisy or opinionated rules are off-listed in the preset, same approach as the base config. The repo root extends the preset (dogfooding); the off-list is verified against the repo's own tests.
- oxlint auto-discovers `.oxlintrc.json`/`.oxlintrc.jsonc` and `oxlint.config.ts`/`.mts`; package imports are not supported in the JSON format, so consumers re-export this package from `oxlint.config.ts` via `defineConfig({ extends: [...] })`. `.gitignore` is respected by default; per-project ignores go into `ignorePatterns`.
- The repo root consumes it via `oxlint.config.ts` (dogfooding): `check:oxlint`/`fix:oxlint` plus the pre-commit lint job; run `pnpm check:oxlint` at the root after edits.
- Type-aware linting is enabled via `options.typeAware` and requires the `oxlint-tsgolint` package — it is declared as an optional peer dependency (`^7.0.2004`) rather than a dependency, so consumers opt in by installing it themselves. Without it the shared config fails hard: consumers must either install `oxlint-tsgolint` or override `options.typeAware` to `false` in their own config. The root keeps it in devDependencies so the root `check:oxlint` finds the `tsgolint` executable. Type-aware options are kept in lockstep with the ESLint type-aware rules where applicable (`prefer-promise-reject-errors` with `allowThrowingAny`/`allowThrowingUnknown`); oxlint-original type-aware rules that fight the codebase style are off-listed in `rules`.
- Versioning/publishing via Lerna from the repo root — never edit `version` by hand.
